# 后端核心缺陷修复

日期：2026-10-23。分支 `codex/backend-core-fixes`。独立测试服务使用 8083，保留原有 8082 服务；测试服务关闭异步任务消费者，防止抢占原实例队列。未修改生产 YAML、凭证或模型能力表。

## 已修复

- 消息发送、历史及 SSE 使用同一发送者补齐逻辑，按去重后的用户列表批量关联昵称。历史系统昵称回退到用户名，注销用户保留身份标记。
- 私聊列表关联另一位成员的显示名称，避免仅显示“私聊会话”。
- 群详情、成员与管理员读取补充成员鉴权；非成员返回 403。
- 群解散改为软删除，删除成员关联并保留消息外键，已有消息的群可成功解散。公开群/消息入口排除已解散会话。
- 群初始人数包含群主；批量邀请过滤重复/空项及已有成员，避免无效批次和计数错误。
- 撤销管理员时空更新列表不再执行无效 SQL。
- 新增 `GET /users/lookup?type=USERNAME|PHONE|PUBLIC_ID&value=精确值`。返回 `public_id`、`username`、`nickname`、`avatar_url`，不返回电话、邮箱、密码或数据库主键。不存在 404、无效参数 400、未登录拒绝访问。Redis 按登录账号限制每 60 秒 10 次有效格式查询，超过限制 429。
- 任务详情显式绑定路径参数，限制只读当前账号任务（组长提交合入）。
- 模型目录仅展示数据库能力、启用候选配置、已实现提供商和凭证配置的交集，防止展示点击后必失败的选项。目录为空表示运行配置不完整，不代表模型成功可用。

## 验证与限制

接手前子 agent 已完成 14 项定向单元测试及 14 项真实接口检查：发送/历史真实昵称、私聊名称、群人数、三项群读取权限、带消息解散、解散后不可写、精确查找与最小返回字段。组长接手后继续执行新增目录过滤测试与统一回归，以最终验收文档为准。

## 仍需明确的服务端契约

当前无会话偏好及逐条消息隐藏接口，前端仅在本账号当前浏览器保存。建议补充：

- `PATCH /conversations/{id}/preferences`：`{pinned:boolean, hidden:boolean}`，仅修改当前成员偏好；置顶排序与分页需一致，新消息恢复隐藏会话。
- `POST /conversations/{id}/messages/hide`：`{message_public_ids:[...]}`，限制数量并检查每条归属；仅隐藏当前用户视图，返回实际处理列表。与“撤回”严格区分。
- `POST /messages/forward`：目标会话与来源消息列表，逐项校验来源可读、目标可写，支持附件授权复制和幂等键，返回逐条结果。当前前端逐条发送可重试，但没有批次原子性。

手机号/用户名查找原来缺失，现已按上面的精确查询契约补充；对“允许被手机号发现”等隐私偏好和更细防枚举策略仍需后续产品规则，不能用全量用户列表替代查找。

## AI 配置修复建议（未自动执行）

数据库能力记录包含 `qwen-turbo`、`qwen3-max-2026-01-23`、`gpt-4o`，当前运行候选为 `deepseek-v4-flash-0731` 和 `qwen-plus-latest`，且仅实现 DashScope 策略，因此有效交集为空。管理员需要选定实际可调用模型，核对该模型的真实任务能力，再让 `ai.chat.candidates`、`ai_model_capabilities` 和默认路由一致；或显式为已验证的数据库模型添加候选配置。不能在未知能力与供应商可用性时直接将现有能力记录批量改名。
